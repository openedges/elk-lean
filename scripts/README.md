# scripts

| Script | Purpose |
|--------|---------|
| `setup_dev.sh` | Explicit, idempotent development bootstrap (`mise run setup`): mise tools (`mise.toml`), elan + the Lean toolchain of `lean-toolchain`, submodules (shallow, pinned), `lake build` with the 0-warning gate, `lake test`; `--check` reports the state of every requirement; `--only oracle\|java-baseline\|wasm-toolchain` prepare the references under `.reference/` and `../elk-rs`; `--no-mise` uses the tools on PATH |
| `build_oracle.sh` | Release build of the elk-rs oracle into `.reference/elk-rs-target` |
| `bump_version.py` | `--check`: the package version agrees between `lakefile.lean`, `Elk/Api.lean` and the npm manifests; `<version>`: sets it everywhere (`VERSIONING.md`) |
| `publish_npm.sh` | Publishes the `@openedges/elk-lean-<triple>` platform packages, then `@openedges/elk-lean`, skipping versions already on npm (`--dry-run`, `--expect-version`; used by `.github/workflows/release.yml` through Trusted Publishing) |
| `oracle_layout.sh` | Lay out one JSON model with the oracle (optional phase trace dir) |
| `compare_model_parity_layouts.py` | Semantic layout JSON comparison (copied from elk-rs) |
| `compare_phase_traces.py` | Per-processor trace comparison (copied from elk-rs) |
| `run_model_parity.sh` | Whole-corpus parity run: oracle vs `elk batch`, merged manifest, report |
| `make_json_manifest.py` | Input manifest from the corpus `.json` models |
| `merge_parity_manifests.py` | Joins the oracle and elk-lean batch manifests for the comparison script |
| `run_random_java_parity.sh` | Random-graph ELK Java parity: generate (`gen_nodesize_graphs.py`) + sanitise (`sanitize_for_java.py`), ELK Java per set with a watchdog, elk-lean (and `--with-oracle` elk-rs) per input with a time limit, outcome/error/layout comparison (`random_java_parity.py`), mismatch classification (`classify_random_parity.py`) → `<out>/report.md`, `details.tsv`, `tests/random_parity/report.md` |
| `gen_option_graphs.py` | Random flat graphs of the non-layered algorithms with random values of their own options ("o" sets of `run_random_java_parity.sh --sets o`: force model, stress dimension, radial compactor/sorter/wedge/translation, mrtree weighting/routing/search order, rectangle packing strategies, VertiFlex strategy, SPOrE processing order) |
| `sanitize_for_java.py` | Copies `gen_nodesize_graphs.py` graphs so that ELK Java's node size calculator validation accepts them ("v" sets; see its docstring for the three changes) |
| `gen_disco_graphs.py` | Random DisCo layout nodes ("c" sets of `run_random_java_parity.sh --sets c`): random components at given positions (labels, ports, edges with sections, the odd self loop and hyperedge), DisCo at the root or on a compound child of a `fixed` root with extensions in both directions, the component layout algorithm (none, `fixed`, `box`, `layered`, `random`, `rectpacking`), `aspectRatio`, spacing, padding, edge thickness, `polyomino.*` |
| `gen_hierarchical_mo_graphs.py` | Random hierarchical (`INCLUDE_CHILDREN`) layered graphs ("h" sets of `run_random_java_parity.sh --sets h`, agents GS/HMO): two or three levels of compound nodes, model order options (cycle breaking, layering, node promotion, `considerModelOrder.*`) on the root and/or compound children, `NO_LAYOUT` nodes (also compound ones, with and without `ALGORITHM`), `noModelOrder`, cycle breaking group ids, layer constraints, self loops and hierarchy-crossing edges; graph k of a seed does not depend on COUNT |
| `gen_wrapping_graphs.py` | Random layered graphs for the features no other set reaches ("w" sets of `run_random_java_parity.sh --sets w`, agent COV): graph wrapping (strategies, cutting/validify strategies, MSD freedom, correction factor, multi-edge options, degenerate aspect ratios), comment boxes (node, port on each side, two nodes, chained, unattached), hypernodes, edge labels (inline, HEAD/CENTER/TAIL, side selection, center label placement, labels on self loops), node/port label placements, splines (CONSERVATIVE/SLOPPY), BK fixed alignments and edge straightening, `mergeEdges`/`mergeHierarchyEdges`, thoroughness, edge thickness, and the `OBJECT` options Java's JSON importer rejects; graph k of a seed does not depend on COUNT |
| `gen_external_port_graphs.py` | Random layered graphs mixing the external-port features ("x" sets of `run_random_java_parity.sh --sets x`, agent EXT): compound nodes of two or three levels with ports on all sides, port constraints (FREE … FIXED_POS, UNDEFINED), `port.side`/`index`/`borderOffset`/`anchor`, port labels and placements, port alignment and spacing, padding, node size constraints/options, mixed INCLUDE_CHILDREN/SEPARATE_CHILDREN/INHERIT with cross-hierarchy edges and hyperedges, inside self loops, interactive layouts with preset external port positions, directions, routings, model order and post compaction options, non-layered compound children (force, mrtree, rectpacking); graph k of a seed does not depend on COUNT |
| `random_java_parity.py` | Driver of `run_random_java_parity.sh` (stages gen, java, lean, rs, report) |
| `classify_random_parity.py` | Groups the random-graph mismatches by origin layout unit (algorithm, difference kinds) and option features with lift |
| `gen_hashset_ops.py` + `java/HashSetOrder.java` | Random `HashSet` operation sequences (tree bins included) replayed on `java.util.HashSet`, printing every iteration order: the differential check of `Elk.Core.Util.JavaHashSet` (fixture `tests/fixtures/spv/hashset_ops*.txt`, suite `spv.javaHashSet`) |
| `java/AsinDump.java` | `Math.asin` bit patterns of the reference JVM for `Elk.Core.Util.javaAsin` (`ELK_ASIN_CASES=<dump> lake test -- --suite spv.javaAsin`) |
| `build_wasm.sh` | WebAssembly build (emscripten) into `plugins/org.eclipse.elk.wasm/dist/`; see that plugin's README |
| `build_runtime_nogmp.sh` | Native Lean runtime rebuilt without GMP (`libleanrt_nogmp.a`), `--check` big-number differential test, `--relink elk` GMP-free CLI; used by `build_ffi.sh`/`build_napi.sh` with `ELK_NO_GMP=1` (see `docs/gmp-licensing.md`); env `RT_OUT`, `RT_EXTRA_CXXFLAGS`, `RT_STAMP_EXTRA`, `AR` for the LTO/PGO runtime of `build_release.sh` |
| `build_release.sh` | Release CLI `.lake/build/release/bin/elk`: Lake's generated C recompiled with Lake's flags + ThinLTO (+ PGO when `.reference/pgo/*.profdata` exists), linked with the no-GMP runtime built as ThinLTO bitcode; also the objects of `build_napi.sh --release`; `--check` byte comparison with the Lake build (see `docs/build-optimization.md`) |
| `build_pgo.sh` | Regenerates the PGO profile under the main checkout's `.reference/pgo/`: LLVM profile runtime of the toolchain clang's commit (sparse fetch of `compiler-rt/lib/profile`), instrumented `build_release.sh --pgo-generate`, training (synthetic bench, Java corpus batch, random s1/v1/w1 × 200), `llvm-profdata merge` (emsdk's, `LLVM_PROFDATA`) |
| `run_java_baseline.sh` | ELK Java 0.12.0 reference layouts of a models directory (unmodified Maven Central artifacts, JDK/Maven from mise, driver `java/`): `java_manifest.tsv`, `inputs/` (ELK's own JSON export of `.elkt`/`.elkg`), `layouts/`; `--trace true` layered phase traces, `--reverse`/`--shuffle` for JVM-context-dependent models, `ELK_JAVA_PATCHES=<dir>` patched overlay |
| `run_java_parity.sh` | Result parity against a Java baseline directory: `elk batch` on exactly Java's inputs, `report_exact.md`/`details_exact.tsv` (tolerance 0) and `report.md` (1e-6) |
| `run_elkt_loader_parity.sh` + `compare_elkt_conversion.py` | ELK Text loader parity: `elk convert` of every `.elkt` of a Java baseline manifest against ELK Java's own JSON export of the model (`inputs/*.elkt.json`), semantically at tolerance 0 after normalising short/full option keys (layered options under their Java id), `10.0`/`10` in option strings, zero geometry, generated ids of duplicate identifiers and the driver's `randomSeed` |
| `run_elkt_layout_parity.sh` + `elkt_layout_manifest.py` | ELK Text end-to-end parity: `elk layout --defaults X.elkt` against `ElkJavaBaseline --live-defaults true` (the elk-live server's default sizes: nodes 30, ports 5, labels 9 x length by 16), tolerance 0; `--include`/`--limit` pass through, `JAVA_REUSE=1` keeps the Java side |
| `run_java_trace_parity.sh` | Layered phase-step trace parity against ELK Java (Java traces via `run_java_baseline.sh --trace true`, `elk batch --trace-dir`, `compare_phase_traces.py --strict-order`, `summarize_trace_report.py`); `JAVA_TRACE_REUSE=1` keeps the Java side |
| `classify_trace_divergences.py` | Classifies the diverged models of a Java trace run by their first difference (`java-nonfinite`, `selfloop-order`, `partition-order`, `other:<Processor>`) |
| `summarize_trace_report.py` | Markdown summary of a `compare_phase_traces.py --batch --json` report (first divergent processor per model, histogram) |
| `java_outcomes.py` | Checks elk-lean outputs against the set of outcomes ELK Java produced in several JVM contexts (forward, reverse, shuffled runs); elk-lean must reproduce one of them |
| `run_timsort_diff.sh` + `java/TimSortTrace.java` | Differential test of `Elk.Core.Util.JavaSort` against JDK 21 `Collections.sort` (13,767 cases: outcome, comparator call sequence hash, permutation hash); `--fixture` regenerates `tests/fixtures/timsort/cases.jsonl` |
| `run_trace_parity.sh` | Corpus phase-step trace parity against the elk-rs oracle (one trace directory per model, `trace_report.json`, `trace_summary.md`) |
| `run_phase_trace_parity.sh` | Phase-step trace parity of one model against the elk-rs oracle (first divergence step) |
| `compare_bytes.sh` | Byte-for-byte comparison of `elk layout --pretty --sort-keys` with the oracle outputs of a model parity run (secondary indicator) |
| `run_perf_benchmark.sh` | Synthetic performance benchmark: oracle `perf_benchmark` (rust_api, rust_native) vs `elk bench` on the 26 scenarios, `compare_perf.py` report and 5% gate against `tests/perf/baseline_lean_api.csv` |
| `run_corpus_benchmark.sh` | Corpus performance benchmark (`--mode models` on both sides over a parity manifest), totals, per-model ratio distribution and slowest models (`compare_perf.py --corpus`) |
| `compare_perf.py` | Performance report from `perf_benchmark`-format CSVs (per scenario, or `--corpus`), with the regression gate (`--baseline`, `--threshold`) |
| `gen_p3_graphs.py` | Layered crossing-minimisation / layering option variants of the "v" sets ("p" sets of `run_random_java_parity.sh --sets p`) |
| `perf/profile_bench.sh` | Samples `elk bench --scenarios S` with macOS `sample` and prints the hottest functions |
| `perf/sample_inclusive.py`, `perf/sample_callers.py` | Inclusive samples of frames matching a regex; attribution of allocation/copy frames to the nearest elk-lean caller |
| `perf/scan_generated_c.sh` | Static checks of the generated C (`.lake/build/ir`) for known Lean performance traps (run-time Float literals, big literals, float boxing; `PLAN.md` 7.1) |
| `perf/scan_modify_order.py` | Finds the `PLAN.md` 7.1 item-16 pattern (array element read then written back after an exclusivity test) in the generated C |

Environment knobs: `ELK_RS_DIR` (default `../elk-rs`), `ORACLE_TARGET_DIR`,
`ORACLE_RUNNER`.
