# Random-graph ELK Java parity

Generated by `scripts/run_random_java_parity.sh` (seeds 1-10, 600 graphs per seed, sets s,v,d,o,p,c,h,w,x, elk-lean limit 15s per input, Java watchdog 60s per model). `s` = `gen_nodesize_graphs.py` output as generated, `v` = the same graphs sanitised for ELK Java's node size validation (`sanitize_for_java.py`), `d` (experiment) = `v` plus ELK Java's algorithm specific option defaults written explicitly (`sanitize_for_java.py --explicit-defaults`), `o` = flat graphs of the non-layered algorithms with random values of their own options (`gen_option_graphs.py`), `p` = the layered roots of `v` with random crossing minimisation / layering options (`gen_p3_graphs.py`, seed = set seed), `c` = DisCo layout nodes with random components and DisCo options (`gen_disco_graphs.py`), `h` = hierarchical (`INCLUDE_CHILDREN`) layered graphs with model order options, `NO_LAYOUT` nodes, group ids and layer constraints (`gen_hierarchical_mo_graphs.py`), `w` = layered graphs with graph wrapping, comment boxes, hypernodes, edge labels, splines, BK alignments and merged edges (`gen_wrapping_graphs.py`), `x` = compound nodes with external ports on all sides, port constraints, labels and alignment, mixed hierarchy handling, cross-hierarchy edges and inside self loops (`gen_external_port_graphs.py`).
